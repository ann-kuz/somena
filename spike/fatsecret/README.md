# Спайк FatSecret: читается ли дневник ru-аккаунта через API

Единственное непроверенное место архитектуры (ADR-0003). Проверяем до строительства ветки еды.
Скрипт `probe.py` — чистый Python 3, без зависимостей.

## Что нужно от тебя (один раз, ~10 минут)

1. **Ключи API.** Зайди на https://platform.fatsecret.com , зарегистрируйся (это отдельный
   «профиль разработчика», не твой food-аккаунт) и создай приложение (Add application).
   Получишь **API Key** и **API Secret** (Application Type можно указать любой, например
   «Mobile Application»).

2. **Запусти на сервере:**
   ```
   export FS_KEY="твой_api_key"
   export FS_SECRET="твой_api_secret"
   python3 /root/somena/spike/fatsecret/probe.py
   ```

3. Скрипт выдаст ссылку — открой её **в браузере, где залогинена в FatSecret именно под своим
   ru-аккаунтом**, нажми «Allow», со страницы скопируй код подтверждения и вставь в скрипт.

4. Скрипт распечатает дневник за вчера и сегодня (JSON с калориями и БЖУ).

## Как понять результат

- **Есть `calories` и распалась на белки/жиры/углеводы** → спайк успешен, строим ветку еды
  на API, ключи и токены передаём бэкенду.
- **Ошибка про регион/страну/доступ** → API ru-аккаунта недоступен на бесплатном уровне;
  включаем план Б: переход на Lifesum (пишет еду в Health Connect, см. ADR-0003).
- **Что-то странное** → пришли мне вывод скрипта целиком, разберу.

## Заметки

- Полученные `access token` и `access secret` долгоживущие — сохрани, они не протухают
  сами по себе.
- Скрипт хранит ключи только в переменных окружения, ничего не отправляет, кроме
  официальных серверов FatSecret.
