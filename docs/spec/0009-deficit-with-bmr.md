# Спека 0009 — Дефицит с обменом веществ

Статус: **ready-for-agent**. Словарь — в [CONTEXT.md](../../CONTEXT.md); правило цветов
и графиков — в [0002](0002-design-system.md); история Дефицита — в [0005](0005-deficit-and-calories-charts.md).

## Problem Statement

Дефицит считается как разница сожжённых и съеденных калорий, но в сожжённое
браслет вкладывает не весь расход: базовый обмен веществ остаётся за кадром, и
линия Дефицита систематически занижена. Обмен веществ (шкала «Обмен») приходит
с умных весов только в дни взвешиваний, а в дни без взвешивания Дефициту нечего
прибавить. Владелица: «прибавляй к графику дефицита последнее значение обмена
веществ с умных весов» и хочет задавать это число вручную, когда весов нет.

## Solution

Дефицит дня теперь: сожжено минус съедено плюс обмен веществ. Обмен берётся с
умных весов - последнее значение на дату; после взвешивания оно несётся вперёд
до следующего. В Профиль добавлено поле «Обмен веществ, ккал/дн»: это запасное
значение, оно работает только пока весы не передали своего. Формула одна везде:
на графике Дефицита (с подписью), в графиках ИИ и в строке дня контекста Чата.

## User Stories

1. Как Пользователь, я хочу, чтобы Дефицит включал обмен веществ, чтобы линия
   показывала полный расход, а не только активные калории.
2. Как Пользователь, я хочу, чтобы последнее значение обмена с весов действовало
   до следующего взвешивания, чтобы дни без весов не выпадали из расчёта.
3. Как Пользователь, я хочу задать обмен веществ вручную в Профиле, чтобы
   Дефицит считался и без умных весов.
4. Как Пользователь, я хочу, чтобы значение с весов было сильнее ручного, чтобы
   приборное измерение не подменялось оценкой.
5. Как Пользователь, я хочу видеть формулу на графике Дефицита, чтобы понимать,
   из чего складывается линия.
6. Как Пользователь, я хочу, чтобы ИИ в Чате считал дефицит по той же формуле,
   чтобы ответы не расходились с графиком.
7. Как Пользователь, я хочу, чтобы ручной обмен проверялся на разумный диапазон,
   чтобы опечатка не уронила линию Дефицита под ноль.

## Implementation Decisions

- **Формула Дефицита:** сожжено минус съедено плюс обмен. Если калорий за день
  нет, день остаётся пропуском (не ноль, спека 0001). Если обмена нет ни с весов,
  ни из Профиля, слагаемое просто не добавляется: старые данные считаются как
  раньше.
- **Приоритет источников обмена:** показание весов за день сильнее последнего
  показания с весов, оно сильнее ручного значения из Профиля. Ручное значение -
  запас на случай «весы молчат».
- **Ручной обмен живёт в Профиле** (вкладка «Ещё»): поле «Обмен веществ, ккал/дн»,
  необязательное, с проверкой диапазона 800-4000 ккал/дн и общей проверкой числа.
  Хранится локально (ADR-0002).
- **Контекст Чата:** строка дня считает Дефицит по той же формуле; ручной обмен
  виден в строке «Профиль» с пометкой «если весы не дали своего», показание весов
  дня - в самой строке дня («обмен ... ккал/дн»).
- **График Дефицита** получил подпись «Сожжено + обмен - съедено»; цвет, порядок
  и правило цветов метрик не менялись.

## Testing Decisions

- Шов прежний - серии метрик и строка контекста Чата: дефицит с обменом весов и
  переносом его вперёд, ручной запас, приоритет весов над ручным, профильная
  строка с обменом. Приор - MetricSeriesTest, ChatContextTest,
  ProfileValidatorTest.
- Экранная часть (поле Профиля, подпись графика) тестом не накрывается:
  дизайн-слой без логики, приёмка по скриншотам на устройстве владелицы.

## Out of Scope

- Ручной ввод обмена за конкретный день (только одно запасное значение).
- Пересчёт прошлых Дневных срезов: перенос обмена вперёд делается на лету.
- Формулы Калорий, БЖУ и остальных графиков.
- Расчёт обмена по формуле (Миффлина-Сан Жеора) из роста, веса и возраста.

## Further Notes

- Показание «обмен» на «Сегодня» и график «Обмен» остались как были: это данные
  весов, а не производная Дефицита.
- Старые записи без обмена считаются по-прежнему: разница сожжённых и съеденных.
