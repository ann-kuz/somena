# Спека 0016: Читатель старого xls

## Problem Statement

Выгрузка весов Fitdays - это на самом деле старый бинарный Excel (Excel 97-2003)
под именем .csv. Приложение читало такой файл запасной кодировкой windows-1251:
таблица доходила до модели со шлаком контейнера вперемешку с читаемыми кусками.
Даты в выгрузке - день вперёд через дробь, и даже выбранная Ступень спека 0015
получала искажённые строки, а не чистую таблицу.

## Solution

Собственный мини-ридер старого xls - без библиотек, как ридеры docx и xlsx. По
магии OLE2 (общая обёртка старых форматов Office) файл уходит в новый ридер, тот
достаёт из контейнера поток «Workbook», проходит записи BIFF8 и собирает первый
лист в текст таблицы: строки через перевод строки, ячейки через таб - тот же
формат, что у xlsx-ридера. Общие строки (SST) читаются с переносом записи
CONTINUE посреди строки, числа - из записей NUMBER, RK и MULRK, строки прямо в
ячейке - из LABEL (латиница байтом, остальное - UTF-16), даты - числа со стилем
даты - переводятся в ISO. Второй и следующие листы не читаются, как у xlsx.
Нечитаемый файл - честный отказ «поддерживаются csv, tsv, xlsx и старый xls»
вместо шлака в модель. Пикер Вложений пускает и настоящий .xls (раньше расширение
не выбиралось).

## User Stories

1. Как Пользователь, я хочу прикладывать выгрузку Fitdays (старый xls под именем .csv) и получать чистую таблицу, чтобы ИИ разбирал даты и показатели без шлака.
2. Как Пользователь, я хочу прикладывать настоящий .xls из проводника, чтобы файлы старого Excel выбирались скрепкой, а не серели в пикере.
3. Как Пользователь, я хочу, чтобы даты-числа со стилем даты приходили в модель датами ISO, чтобы никакая модель не гадала, день это или месяц.
4. Как Пользователь, я хочу, чтобы русские заголовки («Дата, время», «Вес») читались из SST как UTF-16, чтобы таблица не превращалась в кракозябры.
5. Как Пользователь, я хочу, чтобы длинные таблицы, где общие строки рвутся на записи CONTINUE, читались целиком, чтобы строки не терялись и не склеивались.
6. Как Пользователь, я хочу, чтобы файл с несколькими листами разбирался по первому листу, как в xlsx, чтобы поведение обоих форматов было одинаковым.
7. Как Пользователь, я хочу, чтобы битый или чужой OLE2-файл давал понятный отказ с перечнем форматов, а не молчаливую тарабарщину в модели.
8. Как Пользователь, я хочу, чтобы короткие книги читались из мини-стрима контейнера, а длинные - из обычных секторов, чтобы ридер справлялся с файлами любого размера.
9. Как Пользователь, я хочу, чтобы Ступень и вопрос к таблице работали как раньше (спека 0015, спека 0007), чтобы читатель лишь сменил вход, не трогая остальной Разбор.

## Implementation Decisions

- Маршрутизация по магии файла: zip - xlsx, OLE2 - xls, остальное - csv/tsv
  кодировками. Медицинские документы по-прежнему уходят в Разбор документа раньше
  таблиц (их маршрутизация не менялась).
- Контейнер OLE2: заголовок, DIFAT (109 ячеек заголовка плюс цепочка), FAT,
  каталог - обычной цепочкой секторов (как пишут Excel и POI), мини-стрим корня и
  мини-FAT для потоков короче 4096. Поток книги ищется по имени «Workbook»
  (запасное имя «Book»).
- BIFF8: первый лист по подсчёту секций; SST с CONTINUE - курсором, который на
  границе записи перечитывает байт флага 8/16 бит (самое капризное правило
  формата); мусор форматов (rich runs, phonetic) пропускается; LABEL - строка в
  ячейке; NUMBER/RK/MULRK - числа; XF с встроенным или своим датовым форматом
  превращает serial-число в ISO (эпоха 1899-12-30, как у xlsx).
- Формат вывода и лимиты прежние: тот же текст таблицы, те же 60 000 символов и
  2 МБ на Вложение, тот же Разбор со Ступенью из селектора чата.
- Бэкенд не меняется: для него это просто текст таблицы.

## Testing Decisions

- Хороший тест проверяет внешний результат - текст таблицы из байтов файла, - а
  не устройство ридера.
- Шов прежний: чистые функции core, файлы собираются прямо в тесте (как в
  XlsxReaderTest), только вместо zip - собственный сборщик OLE2-контейнера и
  записей BIFF8.
- Покрыто: строки SST (латиница байтом и русский UTF-16), NUMBER, RK (целое,
  делённое на сто, усечённый double), MULRK, LABEL, дырки между ячейками, даты
  со стилем, перенос SST через CONTINUE посреди строки, книга длиннее порога
  (обычные сектора вместо мини-стрима), второй лист, маршрутизация по магии и
  отказ на мусоре.
- Нечитаемый файл - тоже поведение: мусор с магией OLE2 возвращает null, экран
  чата показывает отказ с перечнем форматов.

## Out of Scope

- BIFF5 (Excel 95): восьмибитные строки без SST и прочая археология - читатель
  честно откажется.
- Формулы со строковым результатом: числовой результат читается, строковый -
  пропускается.
- Второй и следующие листы книги.
- xlsx и csv - без изменений.

## Further Notes

Выгрузка Fitdays собрана Java Excel API (jxl) 2.6.3 - книги BIFF8 с общими
строками; покрытых записей хватает. Проверка на телефоне владелицы: Максимальная
Ступень, выгрузка Fitdays, в Предпросмотре - даты летом-осенью 2026 года без
кракозябр в заголовках.
