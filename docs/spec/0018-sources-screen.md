# Спека 0018: Экран Источников - список показателей

## Problem Statement

Приоритет Источников (спека 0014) задавался на одной длинной странице «Настроек →
Данные»: у каждого показателя пронумерованный список приложений с двумя стрелками
у каждой строки и общий абзац объяснений сверху. Понять с одного взгляда, кто
главный по шагам, было трудно: шесть списков со стрелками стояли в куче, а слова
объяснения не отвечали на главный вопрос - «чьи данные я сейчас вижу».

Владелица принесла скриншоты Health Connect как образец читаемости: там список
категорий данных (иконка, название, сводка) ведёт на отдельный экран категории
с приложениями и их иконками.

## Solution

«Источники данных» становятся двумя экранами.

**Список показателей** на «Настройки → Данные»: одна стеклянная карточка со
строками-показателями (Шаги, Сон, Расход, Пульс, Еда, Вес и состав тела) в стиле
меню Настроек - иконка, название, сводка, шеврон. Сводка отвечает «чьи данные»:
«Пишет: Mi Fitness», «Пишут 3 приложения, порядок не задан», «Главный: Mi
Fitness, запасных: 2», «Никто не пишет». Показатели без писавших остаются
приглушённой секцией «Пока никто не пишет» с подсказкой о синхронизации: видно,
что приложение умеет и что можно подключить.

**Экран показателя** (третья ступень подэкранов Настроек): приложения с
настоящими иконками из системы (удалённое приложение - буква на стекле), именем
и свежестью «Последняя запись: сегодня / вчера / N дней назад». Порядок задаётся
перетаскиванием удержанием строки - жест общий с переносом плашек «Сегодня» -
или стрелками как запасным способом (перетаскивание не может быть единственным
способом по правилам доступности). «Все источники» пилюлей возвращает чтение без
порядка. Сводка и подпись свежести - чистая логика в core с тестами; скан
отдаёт последнюю запись каждого Источника.

## User Stories

1. Как Пользователь, я хочу увидеть списком, какие показатели у меня пишутся и
   кто их пишет, чтобы не листать шесть списков со стрелками.
2. Как Пользователь, я хочу, чтобы строка показателя сразу говорила «главный
   сейчас такой-то», чтобы не гадать, чьи шаги я вижу.
3. Как Пользователь, я хочу тапнуть показатель и попасть на отдельный экран
   только про него, чтобы менять порядок в тишине, без остального списка.
4. Как Пользователь, я хочу видеть иконки приложений, чтобы узнавать Mi Fitness
   не читая названий.
5. Как Пользователь, я хочу видеть, когда каждое приложение писало последний
   раз, чтобы понимать, кто «живой», и ставить главного осознанно.
6. Как Пользователь, я хочу перетащить приложение удержанием строки, а могу
   нажать стрелки, чтобы порядок было удобно менять любым способом.
7. Как Пользователь, я хочу видеть показатели, которые никто не пишет, чтобы
   знать, что ещё можно подключить.

## Implementation Decisions

- Сводка строки показателя (`SourceGroupChoice.summary`) и подпись свежести
  (`lastWriteLabel` с русскими формами «день/дня/дней») - чистые функции в
  core/Sources.kt, покрыты тестами вместе со слиянием lastWrite по типам группы.
- `HcSource` несёт `lastWrite` - конец (у мгновенных записей - момент) самой
  поздней записи за окно скана; при слиянии типов группы (вес и состав тела,
  два типа калорий) остаётся самая поздняя.
- Иконки приложений читаются из PackageManager по пакету один раз на строку;
  adaptive-иконки рисуются в bitmap. Удалённое приложение иконки не отдаёт -
  вместо неё буква имени на стекле.
- Перетаскивание - общий жест `detectDragAfterHold` из ui/DragHold.kt (вынесен
  из TodayUi); порядок живёт в состоянии и читается жестом живьём, иначе
  pointerInput со снимком списка тащил бы по старым местам. Изменения порядка
  сохраняются сразу, стрелками или перетаскиванием - одинаково.
- Маршрут третьей ступени - ключ подэкрана «data/<группа>» (`sourceGroupPage`);
  системное «назад» с экрана показателя возвращает в «Данные». Экраны собраны
  из существующих компонентов по спеке 0002 (стекло, пилюля, иконки Material
  filled 22 dp); иконки показателей нарисованы вручную в ui/Icons.kt - extended
  не тянем.
- Логика приоритета не менялась: `applySourcePriority`, хранилище и правило
  «применится при следующем „Обновить“» - как в спеке 0014 и ADR-0010.

## Не сработало и не вошло

- Показывать «кого выбрал сегодня» отдельной строкой: свежесть «Последняя
  запись» у каждого приложения уже показывает, кто живой, а главное место
  виден номером - дубль строк не добавил бы ясности.
- Drag-and-drop как единственный способ: недоступно части Пользователей,
  стрелки остаются всегда.
