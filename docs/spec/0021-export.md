# Спека 0021: Экспорт и восстановление

## Problem Statement

Все данные живут только на телефоне (ADR-0002): отметки Дневных срезов,
Самочувствие, Записи цикла, Медкарта с оригиналами документов в Хранилище,
переписка Чата и настройки. Потеря или смена телефона означает потерю всего,
а перенести данные нечем. Термин «Экспорт» давно ждёт в словаре («один файл,
содержащий все данные Пользователя»: перенос, восстановление, будущий
«отчёт врачу»), а тикет 08 из MVP так и остался нетронутым.

## Solution

В «Настройках → Данные» появляется секция «Экспорт» с двумя действиями.

**«Сохранить копию»** собирает один файл-архив (zip) с именем вида
`somena-export-2026-10-08.zip` и открывает системное окно «куда сохранить»
(Диск, Загрузки, флешка). Внутри архива: манифест (первой записью), копия
базы `somena.db`, настройки `settings.json` и файлы Хранилища под `medcard/`.
Во время сборки виден ход работы; файлы Медкарты копируются потоком, без
копии в памяти. Перед копией базы делается WAL-чекпоинт - файл базы полон
и самодостаточен.

**«Восстановить из копии»** читает манифест (один маленький кусок файла,
без распаковки), показывает, что внутри: дата копии, сколько дней, отметок,
записей, файлов Медкарты - и честно предупреждает: **текущие данные будут
целиком заменены, это нельзя отменить**. Только после явного «Заменить всё»:

1. архив распаковывается во временные файлы и проверяется (манифест, целостность
   базы `PRAGMA integrity_check`);
2. если в копии есть файлы Медкарты, система просит выбрать папку Хранилища -
   Андроид не даёт писать в папку без выбора Пользователем; отмена выбора
   отменяет всё восстановление;
3. база подменяется переименованием (не перезаписью - чужие соединения
   не портят новый файл), настройки перезаписываются целиком;
4. файлы Медкарты переносятся в выбранную папку прямо из архива, адреса
   записей (`file_uri`) переписываются по совпадению имён, папка запоминается;
5. приложение само перезапускается - свежий процесс читает новую базу
   и настройки (миграции поднимают базу старой версии сами).

Совместимость: копия от **старой** версии приложения восстанавливается -
база поднимается миграциями при первом открытии. Копия от **более новой**
версии (формат или версия базы выше) - отказ с подсказкой «обнови приложение».
Битый файл или не копия вовсе - отказ до всякой замены: данные не тронуты.

## User Stories

1. Как Пользователь, я хочу сохранить все свои данные одним файлом, чтобы
   пережить потерю или смену телефона.
2. Как Пользователь, я хочу, чтобы в копию входили и файлы Медкарты, чтобы
   «всё в одном файле» было правдой, а не половиной.
3. Как Пользователь, я хочу видеть, что внутри копии, до того как соглашусь
   на замену, чтобы не угадывать вслепую.
4. Как Пользователь, я хочу, чтобы восстановление ничего не трогало до явного
   «Заменить всё», чтобы случайный тап не стёр мои данные.
5. Как Пользователь, я хочу восстановить копию на свежем телефоне и получить
   всё как было, включая Медкарту и переписку Чата.
6. Как Пользователь, я хочу, чтобы копия от старой версии приложения
   открывалась, чтобы переезд не требовал угадывания версий.

## Implementation Decisions

- Формат - zip, а не JSON и не голый файл базы (ADR-0011): записи-файлы
  Медкарты кладутся в архив как есть, манифест версионирован, предпросмотр
  читается без распаковки. Имя файла даёт дату копии.
- Настройки копируются как все ключи SharedPreferences с типами («строка»,
  «правда/неправда», числа, набор строк), чтобы восстановление вернуло ровно
  тот тип. Исключения: `med_folder_uri` (адрес папки живёт на телефоне; после
  переноса папку выбирают заново) и `app_log` (Журнал - местная диагностика,
  а не данные Пользователя).
- Ключ Чата входит в копию - так решила владелица: после восстановления
  ничего не надо вводить заново. Следствие: файл Экспорта - личный секрет,
  приложение говорит об этом сразу после сохранения.
- Чистая логика в `core/ExportArchive.kt`: манифест, проверки `exportProblem`,
  строки предпросмотра `exportSummary` (русские формы счёта), кодировкa
  настроек `prefsToJson`/`jsonToPrefs` - с тестами. Android-мир в
  `data/ExportManager.kt`: сборка архива, два прохода восстановления,
  обход дерева Хранилища, подмена базы. Экран - `ExportUi.kt`.
- Восстановление идёт в два прохода по архиву: сначала манифест, база
  и настройки во временные файлы (проверки и подмена), потом файлы Медкарты
  потоком в Хранилище - сотни мегабайт не оседают во внутренней памяти.
- Прогресс сборки и переноса пишется в статус секции; кнопки гаснут,
  пока идёт работа.
- Автокопия на сервер - по-прежнему план второй версии (словарь «Экспорт»),
  формат архива для неё и выбран.
