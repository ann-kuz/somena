# Оригиналы Медкарты - обычные файлы в Хранилище, состояние разбора - в базе

До сих пор норма была «Вложение не хранится»: в истории чата остаются только имя файла
и итог разбора, файлового хранилища в приложении нет вовсе. Для Медкарты решено иначе
(спека Медкарты, ход обсуждения с владелицей): оригиналы медицинских документов живут
как обычные файлы в папке на телефоне - Хранилище, выбранной Пользователем через
системный диалог (долговременный доступ к одной папке, без разрешения «на все файлы»).
Записи Медкарты в локальной базе ссылаются на файлы по пути.

Ключевые следствия решения:

- снаружи в Хранилище можно класть, переименовывать и убирать файлы любым способом -
  приложение файлы не удаляет и не переименовывает никогда; оно читает, показывает
  список и отдаёт выбранный файл на Разбор;
- метка «разобран» - состояние записи в базе, а не часть имени файла: во внутреннем
  списке файлов она видна как бейдж в цветах Темы-туманности. Переименование файлов
  («название_parsed») отвергнуто: ломается о внешние переименования и вторгается в
  файлы Пользователя;
- запись переживает пропажу оригинала: файл переименован или удалён снаружи - запись
  живёт со всеми данными и пометкой «оригинал не найден», файл можно привязать заново;
- загрузка скрепкой в Чате кладёт копию файла в Хранилище сама - оба входа Разбора
  (скрепка и выбор файла в Хранилище) оставляют оригинал в одном месте;
- ручные записи без оригинала допустимы (ввод с клавиатуры теми же полями).

Почему не скрытое приложение-хранилище: владелица управляет файлами с компьютера и
проводника, а перепроверяемость извлечённого требует доступного оригинала. Данные
остаются локальными, ADR-0002 не нарушен: Бэкенд по-прежнему ничего не хранит.
