# AGENTS.md — инструкции для агентов в этом репозитории

## Как отвечать на «как скачать приложение»

Приложение скачивается с Бэкенда, два канала (спека 0012):

- **Стабильная сборка** — постоянная ссылка из README (раздел «Скачать приложение»):
  **http://77.239.99.15:8787/apk/somena.apk**
- **Тестовый релиз** — **http://77.239.99.15:8787/apk/somena-test.apk**:
  туда `scripts/build-apk.sh` кладёт каждую сборку автоматически.

Никаких других способов не предлагать (не scp, не GitHub Releases, не «собери сама»).
Ссылки не менять и не версионировать. Стабильную обновляет только
`scripts/promote-apk.sh` и только по явной просьбе владелицы. Если по ссылке 404 —
собрать и опубликовать `scripts/build-apk.sh` (тестовая), стабильную — promote-скриптом;
и только ими.

## Сборка и публикация APK

Только через `/root/somena/scripts/build-apk.sh` (сервер vkbot). Скрипт собирает
debug-APK и кладёт его на тестовую ссылку `backend/apk/somena-test.apk` с записью
версии в `site/version.json`; стабильную ссылку наполняет `scripts/promote-apk.sh`
по явной просьбе владелицы. Каждую правку `app/` заканчивай коммитом и сборкой APK
этим скриптом, подняв версию в `app/build.gradle.kts` (фича - минор, правка - патч);
отдельная просьба не нужна.
После правки `backend/app.py` — `systemctl restart somena-ai` (см. backend/README.md).

## Тикеты

Трекера нет. Тикеты фичи живут в `.scratch/<слаг-фичи>/issues/NN-слаг.md`: номер задаёт
порядок зависимостей, блокировки - в поле «Blocked by» каждого тикета, статус
`ready-for-agent` означает «можно брать». Пример: `.scratch/somena-mvp/issues/`.

## Остальное

- Отвечай владелице без сложных технических терминов; любые действия, требуемые от неё,
  описывай подробно по шагам.
- Словарь домена и «избегать»-термины: CONTEXT.md. Говори словами словаря.
- Дизайн любых экранов: docs/spec/0002-design-system.md обязателен.
- Юнит-тесты — только чистая логика в `app/src/test/.../core/` (без Android-зависимостей,
  эмулятора на сервере нет). Полный прогон: `gradle :app:testDebugUnitTest`.
