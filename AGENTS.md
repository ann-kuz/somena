# AGENTS.md — инструкции для агентов в этом репозитории

## Как отвечать на «как скачать приложение»

Скачивание двумя каналами; основные ссылки - GitHub (из РФ без VPN), сервер -
запасные (спека 0012 с дополнением про РФ):

- **Стабильная сборка**: **https://github.com/ann-kuz/somena/releases/latest/download/somena.apk**
  Запасная (сервер): **http://77.239.99.15:8787/apk/somena.apk**
- **Тестовый релиз**: **http://77.239.99.15:8787/apk/somena-test.apk** - туда
  `scripts/build-apk.sh` кладёт каждую сборку автоматически.
- **Лендинг**: **https://ann-kuz.github.io/somena/** (зеркало: http://77.239.99.15:8787/)

Никаких других способов не предлагать. Ссылки не менять и не версионировать.
Стабильную обновляет только связка «`scripts/promote-apk.sh` + пуш тега v<версия>»
и только по явной просьбе владелицы.

## Сборка и публикация APK

Только через `/root/somena/scripts/build-apk.sh` (сервер vkbot). Скрипт собирает
debug-APK и кладёт его на тестовую ссылку `backend/apk/somena-test.apk` с записью
версии в `site/version.json` (правку version.json коммитить вместе с остальным).
Каждую правку `app/` заканчивай коммитом и сборкой APK этим скриптом, подняв
версию в `app/build.gradle.kts` (фича - минор, правка - патч); отдельная просьба
не нужна.
Просьба «сделай стабильной» = `scripts/promote-apk.sh` (серверные ссылки) + пуш
тега `v<версия>` (GitHub Actions соберёт и выложит релиз, обновит постоянную
ссылку releases/latest).
После правки `backend/app.py` — `systemctl restart somena-ai` (см. backend/README.md).

## Тикеты

Трекера нет. Тикеты фичи живут в `.scratch/<слаг-фичи>/issues/NN-слаг.md`: номер задаёт
порядок зависимостей, блокировки - в поле «Blocked by» каждого тикета, статус
`ready-for-agent` означает «можно брать». Пример: `.scratch/somena-mvp/issues/`.

- Отвечай владелице без сложных технических терминов; любые действия, требуемые от неё,
