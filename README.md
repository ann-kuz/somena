# Somena

Личный трекер здоровья: шаги/сон/пульс (Mi Band → Mi Fitness → Health Connect),
вес и состав тела (Fitdays → Health Connect), еда дневными итогами (FatSecret →
Health Connect), самочувствие (3 шкалы 0–10 + заметка), календарь цикла, графики,
ИИ-чат по данным. Данные живут только на телефоне: аккаунтов и облаков нет.

- Сайт приложения: **https://elunaris-vitrail.strangled.net/** (зеркала:
  https://ann-kuz.github.io/somena/ и http://77.239.99.15:8787/)
- Словарь проекта: [CONTEXT.md](CONTEXT.md)
- Решения: [docs/adr/](docs/adr/) — Health Connect как единственная точка чтения (0001),
  локальные данные без аккаунтов (0002), еда дневными итогами из FatSecret (0003/0004).
- Спеки: [docs/spec/](docs/spec/) — MVP (0001), дизайн-система «ночная туманность» (0002),
  Лендинг (0012).

## Скачать приложение

Раздача с нашего сервера через домен (открывается из России без VPN), двумя
каналами; у GitHub есть зеркало на случай блокировок. Подробная инструкция для
телефона — на [сайте](https://elunaris-vitrail.strangled.net/#download):

- **Стабильная сборка**: **https://elunaris-vitrail.strangled.net/apk/somena.apk**
  — обновляется вручную после проверки владелицей; по ссылке всегда последняя
  проверенная версия. Зеркало (GitHub):
  https://github.com/ann-kuz/somena/releases/latest/download/somena.apk
- **Тестовый релиз**: **https://elunaris-vitrail.strangled.net/apk/somena-test.apk**
  — сюда каждая сборка попадает автоматически: новое раньше, недоделки возможны.

1. Открой ссылку в браузере телефона — APK скачается сам.
2. Нажми на скачанный файл; Android спросит разрешение «устанавливать из этого
   источника» для браузера — разреши и подтверди установку.
3. Обновление ставится той же ссылкой поверх старой версии (данные не теряются).
4. Для Чата по данным зайди в Настройки → Чат и выбери режим: «Популярные API»
   (модели proxyapi с адресами и ценами, нужен только ключ, инструкция внутри)
   или «Свой API» (адрес, ключ и название модели вручную; подойдёт любой сервис
   формата OpenAI, Claude или Gemini). Режим «через сервер Somena» работает по
   домену https://elunaris-vitrail.strangled.net (с версии 0.29.2 он в приложении
   по умолчанию); адрес с портом 8787 из России не открывается — провайдеры режут
   нестандартные порты.

Проверка живости сервера без телефона: `curl -s https://elunaris-vitrail.strangled.net/health`.

## Форк и сборка из исходников

Проект открыт для форка. Всё собирается стандартным Gradle, подпись debug — для
личного использования этого достаточно.

Требования:

- JDK 17 (`java -version` должен показать 17.x)
- Android SDK; путь задаётся переменной `ANDROID_HOME` или файлом
  `local.properties` со строкой `sdk.dir=/путь/к/Android/sdk`
- Gradle 8.x (wrapper в репозитории нет — используется системный)

Сборка:

```
git clone https://github.com/ann-kuz/somena.git
cd somena
gradle :app:assembleDebug
# результат: app/build/outputs/apk/debug/app-debug.apk
```

Полезно знать:

- Версия приложения — `versionName`/`versionCode` в `app/build.gradle.kts`;
  договорённость проекта: фича — минор, правка — патч.
- Юнит-тесты — чистая логика без Android-зависимостей: `gradle :app:testDebugUnitTest`.
- В репозитории есть серверный сценарий публикации `scripts/build-apk.sh`
  (сборка + выкладывание APK + запись версии). Для своего форка скопируй его и
  поправь пути и адрес раздачи, либо забирай APK из `app/build/outputs/` руками.
- Приложение обращается к Бэкенду по фиксированному адресу; для работы Чата по
  данным нужен свой Бэкенд (следующий раздел) либо режим «Свой API» с ключом
  прямо в приложении — тогда сервер не нужен вовсе.

## Свой Бэкенд

Бэкенд — маленький FastAPI-прокси к ИИ (ключи и доступ из РФ) плюс раздача APK
и сайта. Данные пользователей на нём не хранятся. Подробности: [backend/README.md](backend/README.md).

```
cd backend
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env   # вписать PROXYAPI_KEY и APP_TOKEN
venv/bin/uvicorn app:app --host 0.0.0.0 --port 8787
```

Секреты из `.env` (в git не попадает):

- `PROXYAPI_KEY` — ключ proxyapi.ru (или своего провайдера через `PROXYAPI_BASE`)
- `APP_TOKEN` — токен приложения; его же вписать в приложении: Настройки → Чат
- `MODEL_FAST`, `MODEL_MAX` — модели Ступеней «Быстрая»/«Максимальная»

Для службы systemd — юнит из трёх строк `ExecStart`/`WorkingDirectory`/
`Restart=on-failure` (образец: `backend/README.md`), затем
`systemctl enable --now <имя>`; проверка: `curl -s http://127.0.0.1:8787/health`.

## Сборка и публикация на сервере (сервер vkbot, 1 ядро / 2 ГБ + swap)

Раздача всегда через скрипты и автоматическую сборку на GitHub:

- `/root/somena/scripts/build-apk.sh` — собирает debug-APK и кладёт его на
  тестовую ссылку (`somena-test.apk`), записывая версию в `site/version.json`
  (изменение потом коммитится вместе с остальным).
- «Сделай стабильной» = `scripts/promote-apk.sh` на сервере + пуш тега
  `v<версия>` в GitHub: сборка на GitHub Actions выложит релиз с файлом
  `somena.apk`, и постоянная ссылка `releases/latest/download/somena.apk`
  начнёт отдавать эту версию. Запускается только по явной просьбе владелицы.

Не собирать APK вручную мимо скрипта и не придумывать другие способы раздачи —
ссылки из раздела «Скачать приложение» должны оставаться единственной правдой.
Первая сборка медленная (зависимости + swap). `gradle.properties` уже ограничивает
память, демон выключен намеренно — не включать без причины, сервер маленький.

## Как ведётся проект

Проект ведётся агентами по инженерным скиллам Matt Pocock
([github.com/mattpocock/skills](https://github.com/mattpocock/skills)):

- **grilling / grill-with-docs** — интервью до общей картины: решение считается
  принятым, когда отвечены все вопросы без догадок;
- **to-spec** — разговор превращается в спеку в `docs/spec/` (шаблон: проблема,
  решение, истории, решения по реализации);
- **to-tickets** — спека режется на тикеты с зависимостями;
- **implement / tdd** — реализация по тикетам, тесты — только чистая логика;
- **code-review** — ревью изменений по стандартам репозитория и по спеке;
- **domain-modeling** — словарь домена [CONTEXT.md](CONTEXT.md) и архитектурные
  решения [docs/adr/](docs/adr/) пополняются в момент, когда термин устоялся.

Словарь домена обязателен к употреблению, «избегать»-термины — в каждом определении.
